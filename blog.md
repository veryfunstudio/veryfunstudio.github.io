Studio notes on designing calm, readable puzzle games.

- [Why Tile Journey Works Offline](https://veryfunstudio.github.io/blog/why-tile-journey-works-offline) (2026-06-28): Tile Journey has thousands of 3D levels and works fully offline. Here is how we package content so the game survives commutes, flights, and dead zones.
- [The Logic Behind Arrow Out's Handcrafted Levels](https://veryfunstudio.github.io/blog/the-logic-behind-arrow-outs-handcrafted-levels) (2026-06-24): Arrow Out is easy to learn and quietly hard to put down. Every level is designed by hand so the solution path feels intentional, not random.
- [Why Our Puzzles Avoid Timers](https://veryfunstudio.github.io/blog/why-our-puzzles-avoid-timers) (2026-04-10): Timers create urgency, but they often clash with spare-attention design. Here is how we replace countdown pressure with tension that lives inside the board itself.
- [Designing a Readable Board](https://veryfunstudio.github.io/blog/designing-a-readable-board) (2026-03-25): A mobile puzzle has only seconds to explain itself. The board must teach the player before any tutorial appears.
- [Keeping Mobile Builds Light](https://veryfunstudio.github.io/blog/keeping-mobile-builds-light) (2026-03-10): Casual puzzle games should feel instant. We tune runtime, art, and interaction choices around low-friction play.
- [Store Pages Need Honest Screens](https://veryfunstudio.github.io/blog/store-pages-need-honest-screens) (2026-02-20): A store page is the first usability test for a puzzle game. Screenshots should show the real board, not a fantasy of it.
